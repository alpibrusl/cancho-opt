numerical optimisation · one command line

Minimise anything a program can score.

opt asks your program for the loss at a point and moves on. The iterates are scipy's, bit for bit where that was checked, and a refusal names its rule and the repair.

What it gives you

scipy's iterates

Nelder-Mead, BFGS and SPSA are ports checked against scipy and Qiskit: the same points, bit for bit for the first, with the last bits of BFGS depending on the BLAS (see the evidence).

The objective is a program

It reads the point on standard input and prints one number (BFGS: the value, then the gradient). No library, no binding, any language.

Refusals are data

An error is one JSON line with a stable opt. rule, an exit status and a repair. No payload is ever logged.

What the promise does not establish: that the minimum found is the global one (the XOR story), that your gradient is right (the gradient story), or that it is fast for a cheap objective (scipy in the same process is faster; every evaluation here costs a process start). The stories show each.

What it did on small problems.

Each is a real run, written into the page by a script, with what it shows and what it does not. The data are invented and seeded.

Eight points no line separates

BFGS converged in 15 evaluations, to within 7.6e-13 of an independent Newton solve.

XOR: converged is not solved

BFGS reported converged from 8 of 8 starts; the network classifies all four points from 1.

A loss you can only sample

After 300 iterations the true loss went from 0.6931 to 0.376; the optimum is 0.2308.

A loss with corners

Nelder-Mead reached a loss of 1.4e-13 in 2039 evaluations.

Check the gradient before you trust BFGS

A gradient missing its ridge term made BFGS stop with precision loss at 0.258, above the optimum 0.2308; a doubled bias gradient still converged.

A model whose loss is computed by GPU kernels not run here

12 evaluations, within 1.1e-5 of the normal-equations solution, 28 to 36 ms an evaluation, on cancho-gpu's CPU interpreter.

How it works.

One command: opt minimize --x0 LIST [--method nelder-mead|bfgs|spsa] -- PROGRAM ARG.... For each point opt starts the program, writes the point on its standard input as numbers separated by spaces, and reads the answer from its standard output.

nelder-mead

  • needs only a value
  • handles corners and noise-free but non-smooth losses
  • bounds with --lower and --upper

bfgs

  • needs the value, then the gradient, on one line
  • scipy's two line searches
  • no bounds

spsa

  • needs only a value, and tolerates noise
  • two evaluations an iteration whatever the dimension
  • no convergence test: it runs its iterations

At most 32 parameters and 10^7 evaluations. The program's environment is PATH and HOME=/tmp only, and opt starts it by the name given, without searching PATH: give an absolute path to the interpreter.

A real run.

A fit, then a refusal with its repair, as opt printed them (numbers rounded to six significant digits).

$ opt minimize --method bfgs --x0 0,0,0 -- python3 examples/train/logistic.py
{"method":"bfgs","x":[2.28644,2.41774,2.04962e-16],"fun":0.230847,"jac":[2.95476e-07,5.44138e-09,-1.38778e-17],"nfev":15,"njev":15,"nit":14,"converged":true,"message":"Optimization terminated successfully."}

$ opt minimize --x0 1,1 -- nosuch-program
{"error":"opt.objective-failed","message":"the objective program could not be started","repair":"check the path after `--`; its environment is PATH and HOME=/tmp only","point":[1.0,1.0]}
# exit status 2

What exists, and what does not.

Built

  • minimize with Nelder-Mead, BFGS and SPSA
  • four built-in objectives for trying it: sphere, Rosenbrock, quadratic, absolute
  • a program as the objective, and a refusal that names the point it failed at
  • examples/train: a convex fit, a small network, a noisy loss, a loss with corners and a gradient check

Not built

  • Levenberg-Marquardt and a residual protocol
  • root, curve-fit, L-BFGS-B
  • a finite-difference gradient (BFGS without a gradient is refused: opt.no-gradient)
  • more than 32 parameters

Measured, not promised.

Every claim says what was run, where, and by whom. This repository has no CI yet: the scipy and Qiskit checks are runs made by hand on the maintainer's machine and reported in the README and design.md; they were not rerun for this page (this container has no scipy).

Use it for

  • An objective that costs milliseconds or more (a simulator run, a model fit)
  • A result an agent can read: JSON, a rule, a repair
  • Reproducing scipy's iterates without Python

Not for

  • A cheap objective in a Python loop: scipy in the same process is far faster
  • More than 32 parameters, or training a large model
  • BFGS without a gradient, or with bounds

Try it.

You need the cancho compiler at the commit pinned in cancho.toml, and Rust to build it.

git clone https://github.com/alpibrusl/cancho
git clone https://github.com/alpibrusl/cancho-opt && cd cancho-opt
REV=$(sed -n 's/^cancho = "\([0-9a-f]*\)".*/\1/p' cancho.toml)
(cd ../cancho && git checkout "$REV" && cargo build --release -p cancho)
../cancho/target/release/cancho build --bin opt
build/opt minimize --x0 -1.2,1 --objective rosenbrock

Then examples/train for a program as the objective. OPT=build/opt python3 scripts/gen_stories.py --check reruns what this page shows.
